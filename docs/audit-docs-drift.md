# Audit — docs vs code drift

Status: Findings (not Locked). Date: 2026-09-19. Audited against `dev`.
Scope: `docs/*.md` (Locked and Draft), the four materialized root artifacts
(`AGENTS.md`, `BRAND.md`, `DESIGN.md`, `MODEL_CARD.md`), `.claude/agents/*.md`, and the code each
claim describes.

Read-only. The rules under test: build only against Locked docs; a change to a Locked doc needs a
Change Record; materialized artifacts must not diverge from their canonical source.

## HIGH

### 1. RFC-1 (Locked) froze a permission catalog that does not exist in code
`docs/rfc-arkilaunch-tenancy-rls-auth.md:347-355` · `packages/shared/src/permissions.ts:4-32`

RFC-1's seed catalog is labelled "illustrative codes; **frozen when RFC is approved**" and lists
`settings:manage`, `users:manage`, `reports:read`, `booking:manage`, `catalog:read`,
`platform:tenant:manage`, `platform:subscription:manage`. None of these exist in
`PERMISSION_CODES`, which has `user:manage`, `report:read`, `booking:create`, `booking:read`,
`tenant:manage`, `tenant:approve`. `PermissionCode` is a literal union consumed by
`require-permission.decorator.ts:5`, so the doc's codes would not compile. A Locked doc is frozen
on a catalog the system never used.

### 2. PRD and SDD (Locked) claim breakdown status is extracted; nothing extracts it
`docs/prd-arkilaunch.md:58,368` · `docs/sdd-arkilaunch.md:875` ·
`packages/document-intelligence/src/model-registry.ts:45`

PRD §8: "For EDTRs it extracts active hours, idle hours, and breakdown status." Code:
`EDTR_REQUIRED_FIELDS = ['hours_active', 'hours_idle']`, and `jobs/src/edtr-ocr-worker.ts:178-216`
persists only `hoursActive`/`hoursIdle`. `breakdown_status` appears only in test fixtures
(`packages/db/src/seed/ocr-fixtures/golden-set.ts:16-18`). The claim propagates into the
materialized `MODEL_CARD.md` ("hours + breakdown") via `docs/aia-arkilaunch.md:44`, so the
assurance dossier overstates the AI component's scope.

### 3. DESIGN.md has been hand-edited and now diverges from the Locked DSD
`DESIGN.md` vs `docs/dsd-arkilaunch.md` §2-§8 (DSD Locked 2026-08-02)

`docs/dsd-arkilaunch.md:576` states BRAND.md and DESIGN.md are "materialized from this DSD, *never
hand-edited as source of truth*". DESIGN.md carries content found nowhere in the DSD:

- Build-status annotations on five components, e.g. `DESIGN.md:222` "**Built:**
  `apps/web/src/components/status-pill.tsx`" (also confidence-chip, gauge-readout,
  hazard-divider, weather-banner), and `:230` "**Not yet built**".
- A behavioural rule at `:228` — "A cached reading renders as the dedicated `weather-stale` tone
  rather than keeping its last-known severity color" — implemented
  (`apps/web/src/components/weather-banner.tsx:5,30`) but absent from the DSD.
- `:405` "this document was hand-updated in the same pass, not regenerated by tooling" — the
  artifact admits the hand-edit.

Compounding it, `docs/index.md` §4 asserts "AGENTS.md §5.2 was re-materialized 2026-09-13 …; the
other three are current", which is false for DESIGN.md. Because the DSD is Locked,
re-materializing in either direction now needs a Change Record; none exists.

### 4. Pagination shipped as a wire-contract change with no Change Record
PR #26 — `95a9b33`, `fb1e3ce`, `044189b`, `a6a410c`, `8c58a4e`

`apps/api/src/fleet/fleet.controller.ts:24` now takes `EquipmentListQueryDto`, and the paged
response shape is defined in `packages/shared/src/fleet.ts:16,113` — a change to the response body
of four already-shipped endpoints (equipment, sites, incidents, rate cards) plus a new
`apps/web/src/components/pagination.tsx`. Grepping all 20 CRs for `pagina|pager|pageSize|offset`
returns nothing relevant. This is precisely the shipped-surface change the CR rule exists for.

## MEDIUM

### 5. RFC-1 says `owner` explicitly lacks `*:manage`; the seed grants it two
`docs/rfc-arkilaunch-tenancy-rls-auth.md:352` · `packages/db/src/seed/permission-catalog.ts:86`
RFC-1: "`owner` | `reports:read`, `quote:read`, `fleet:read` | **Explicitly lacks:** any
`*:create` / `*:manage` (US-10: cannot data-enter)". Seed:
`owner: ['quote:read','report:read','booking:read','billing:read','user:manage','tenant:manage']`.

### 6. RFC-1 still names `/app/kyc`; that route was renamed
`docs/rfc-arkilaunch-tenancy-rls-auth.md:353,434` · `apps/web/src/routes/kyc.tsx:240-242`

exactly this rename on 2026-09-17 (`prd-arkilaunch.md:211`) but did not propagate to RFC-1, which
is equally Locked and where the stale path is load-bearing for an authz rule.

### 7. PRD §5.2 IA tree lists two checkout routes that do not exist
`docs/prd-arkilaunch.md:225` · `apps/web/src/routes/account.checkout.tsx:220-222`
PRD lists `/account/checkout`, `/account/checkout/confirm`, `/account/checkout/success`. Only
`path: '/account/checkout/$bookingId'` is registered; there is no bare `/account/checkout` and no
`/confirm` in `apps/web/src/router.tsx:78-131`. The rest of the §5.2 tree matches the shipped
router, so this survived the 2026-09-17 IA reconciliation CR.

### 8. RFC-2 describes a two-call Azure DI flow; the worker makes one call
`docs/rfc-arkilaunch-ocr-edtr-reconciliation.md:55` · `jobs/src/edtr-ocr-worker.ts:160`
RFC-2: "The worker calls Azure DI: **Read for handwriting plus the labeled custom neural model**
for the EDTR fields." Code: a single `await port.analyze(EDTR_MODEL_ID, bytes)`.
`resolveModelRequest` (`model-registry.ts:49-58`) maps only the KYC id to `prebuilt-layout` +
queryFields; no `prebuilt-read` request shape exists in `azure-adapter.ts:77-112`.

### 9. Locked DSD font-loading spec contradicts both the code and its own artifact

`:513` "Font budget <= 90KB" vs DESIGN.md `:385` "<= 90KB (Console) / <= 110KB (Marketing)". Code
follows the artifact; the Locked canonical doc is the stale one.

## Clean

- **Broken cross-references:** clean. Every relative `.md` link in `docs/*.md` and the four root
  artifacts resolves; every file in `docs/` is referenced from `docs/index.md` and every
  `index.md` entry points at an existing file.
- **`.claude/agents/*.md` vs `docs/sad-arkilaunch.md`:** clean. All five cards materialize
  faithfully — names, `description` from the Spawn trigger, `tools`, and the model map
  (fast→haiku, balanced→sonnet, deep→opus) match SAD §3/§5, with no orphan files and no card
  missing a file. `edtr-ocr-worker.md` adds "(default 0.90)" to the confidence-gate rule, which is
  accurate to RFC-2 §4 (`:71`), not drift.
- **`BRAND.md` and `MODEL_CARD.md`:** clean. BRAND diffs against DSD §0/§0.5/§1/§2.2/§2.4/§8.4/§8.6
  with only the expected renumbering and cross-reference rewrites. MODEL_CARD matches AIA
  §1.1-1.3 faithfully — its breakdown-status claim is finding #2's, inherited from the AIA rather
  than introduced here.
- **Reconciliation gating / money path:** clean. SDD §5 (`:580`) and QAD-T26 (`:118`) both match
  `apps/api/src/edtr/edtr.service.ts:374-394` (409 on `discrepancy`, deducts nothing), `:396-421`
  (FOR UPDATE pair lock) and `:609-612` (`gate_passed: true` only after the gate);
  `apps/api/test/money-path.spec.ts:181-274` asserts it.
- **CRs describing work never shipped:** none. All 98 repo-relative paths and all 60 endpoints
  named across the 20 CRs were existence-checked. The three missing files are each recorded as
  deleted by a later CR, and the five missing endpoints are each explicitly recorded as not built
  or rejected.

**Coverage caveat:** the CR sweep verified all path and endpoint claims exhaustively plus a
claim-by-claim read of the two highest-risk CRs. A symbol-level sweep of every backticked
identifier was still running at cutoff and had produced no findings.
